# Project Documentation

This folder stores durable project context so future agents can understand the
project without requiring the full conversation history.

## What belongs here

- Architecture decisions and their reasons
- Current AWS resources and deployment notes
- Important API and database contracts
- Authentication and authorization decisions
- Known limitations and temporary workarounds
- Debugging findings and fixes
- Sprint summaries and next steps
- Explanations of concepts the learner is studying

## Documentation guidelines

- Write concise, factual notes.
- Include dates when information may change.
- Record why a decision was made, not just what was chosen.
- Never record secret values, credentials, API keys, or session tokens.
- Update existing context instead of creating duplicate notes when practical.
- Agents should read relevant documentation before beginning work.
